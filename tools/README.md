# tools/

Test harnesses that prove the SPEC §17 SLOs with automated evidence. Each harness becomes its own
pnpm workspace (`tools/<name>` with a `package.json`) when it is built; this folder has none yet, so
pnpm ignores it until then.

| Harness                                              | What it proves                                                                                                                                                                                                                                                                                                                                                                                                                                   | Arrives in                                           |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| `tools/isolation-switch` (overlay isolation harness) | I-1..I-6: randomized sequences of team switches, Next Match, theme pushes, worker failovers, and reconnects (>= 1,000 transitions); sample output frames and compare against the expected session's snapshot (region compare or embedded per-session marker). **Pass = 0 mismatched frames.** Runs against both the cloud compositor and the on-device renderer (ADR-019). Nightly and on PRs touching overlay/realtime/compositor/client state. | M14 (first cut against M06 overlay + M07 compositor) |
| `tools/netem-chaos` (netem chaos profiles)           | Input dropout and recovery: `tc netem` profiles (loss, jitter, outage) on the contribution leg, plus ingest restart, worker kill, realtime DO restart, API outage during scoring. Output must stay live on slate; camera resumes <= 3 s after return; worker failure resumes <= 15 s.                                                                                                                                                            | M07 (basic dropout) then M14 (full profile set)      |
| `tools/compositor-soak` (compositor soak)            | Stability over long sessions: 4-hour multi-session soak on one GPU host with memory/process leak checks and dropped-frame accounting.                                                                                                                                                                                                                                                                                                            | M01 (short spike soak) then M14 (4 h)                |
| `tools/score-latency` (score-latency probe)          | Score-to-screen latency <= 1 s p95: timestamped scoring events -> detection of the change in output frames; reports p50/p95.                                                                                                                                                                                                                                                                                                                     | M01 (spike measurement) then M14 (reported)          |

Conventions when they land: TypeScript, Vitest for any pure logic, `@rocketcast/config` presets,
results written as JSON under `tools/<name>/results/` (git-ignored) and summarized in the milestone
NOTES file. Mobile soak and airplane-mode E2E live with the mobile app (Maestro), not here.
